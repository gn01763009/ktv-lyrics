# 發佈前驗收清單

這份清單由提案人在自己的 Mac 上逐項執行並填寫。每一項都要記錄實際結果：通過、失敗或未測。Apple Music 是首次實測，失敗要照實回報，不要跳過。

## A. 放行與安裝

| 編號 | 項目 | 操作 | 預期 | 結果 | 備註 |
|---|---|---|---|---|---|
| A1 | 未公證版本的放行流程 | 1. 執行 `make release`。2. 把 `build/KTV-Lyrics.zip` 解壓到一個測試用資料夾。3. 在該資料夾的終端機執行：`xattr -w com.apple.quarantine "0081;$(printf %x $(date +%s));Safari;" "KTV Lyrics.app"`，模擬下載後的隔離標記。4. 雙擊打開 app。 | 記錄 macOS 26.4.1 實際出現的每一個提示與點擊的按鈕，以及在「系統設定」中需要做的步驟。不要套用其他版本的流程。 | | |
| A2 | 重新編譯後的權限 | 1. 執行 `make install`。2. 允許控制 Spotify，播放一首歌確認字幕正常。3. 再執行一次 `make install`，然後重新打開 app 並播放歌曲。 | 記錄第二次是否再次要求允許控制 Spotify。結果寫回 README 的「權限」一節。 | | |

## F. 長時間與異常情況

| 編號 | 項目 | 操作 | 預期 | 結果 | 備註 |
|---|---|---|---|---|---|
| F1 | 閒置 CPU | 結束播放（或暫停超過 1 分鐘，字幕已消失），讓 app 閒置 2 分鐘，用「活動監視器」觀察 KTVLyrics 的 CPU 用量。 | 接近 0%，明顯低於播放中的用量。 | | |
| F2 | 長時間暫停 | 播放有字幕的歌，暫停。 | 暫停 1 分鐘內字幕留在畫面上；超過 60 秒後字幕消失。按下播放後字幕立刻回來。若一開始就是暫停狀態開啟 app，播放前不顯示字幕。 | | |
| F3 | 結束播放器不會被叫回 | 播放歌曲後直接結束 Spotify（或音樂 app），等 10 秒，觀察 Dock 與「活動監視器」。 | 播放器沒有被 KTV Lyrics 重新打開。 | | |
| F4 | 離線再上線 | 1. 關閉 Wi-Fi，播放一首沒查過的歌。2. 打開 Wi-Fi，換歌再回到這首歌。 | 離線時顯示「暫時查不到字幕，下次播放會再試一次」。上線後再播放同一首歌可以找到字幕（沒有被當成找不到而記住 24 小時）。 | | |
| F5 | 第一次的權限提示 | 第一次執行 app（或用 `tccutil reset AppleEvents` 重設後），播放 Spotify 或音樂 app 的歌曲。 | 記錄 macOS 是否出現「控制 Spotify／音樂」的詢問、要點的按鈕，以及不允許時字幕的行為。 | | |
| F6 | 失敗提示蓋過字幕 | 字幕顯示中匯入一個沒有時間標籤的文字檔。 | 「匯入失敗」提示出現在字幕上方，約 6 秒後消失，字幕維持原狀。 | | |
| F7 | 字幕可靠近邊緣 | 在設定中把水平與垂直位置滑到最左、最右、最上、最下。 | 字幕文字貼近螢幕對應的邊緣，整段滑桿都有作用。 | | |
